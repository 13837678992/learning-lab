# TraceKeep（证迹）
## Android 本地取证工具｜分阶段产品需求、法律证据能力设计与 CLI 执行手册

> 版本 1.0｜2026-10-29｜法律适用范围：暂按中国大陆场景设计，正式实施前需律师复核

# 0. 阅读须知与核心结论

## 重要法律边界

- 本项目不能、也不应承诺“完整法律效力”“法院必然采信”或“录制后自动成为有效证据”。证据是否被采纳，需要结合真实性、合法性、关联性、形成过程、原始载体、举证质证以及个案情况综合判断。
- 本项目的工程目标是提高证据材料的可解释性、完整性、可复核性和保存质量，并尽可能引入独立第三方的时间证明、身份认证、存证或公证服务。第三方服务也不能自动证明录制内容在形成之初就是真实的。
- 哈希只能用于比较字节是否一致；哈希链只能帮助发现特定的日志变动；数字签名可验证特定密钥签署的内容；可信时间戳或第三方存证可支持某个数据在某个时间点已存在或已被提交。任何单项技术都不能单独证明现场事实真实、录制过程完整或行为合法。
- 本文件是产品与工程需求，不是法律意见。上线前应由熟悉中国大陆民事诉讼、电子数据证据和个人信息保护的律师审阅具体场景、告知文案、隐私政策、第三方服务合同及证据导出流程。

## 法律设计依据（官方来源）
请严格按照以下要求修改 TraceKeep 安卓本地取证工具的实现，不要仅在文档中说明法律条款，必须落实到代码、数据结构、操作流程和导出结果中。

1. 原始证据保护

采集到的原始文件必须保留原始内容，不得覆盖、修改、压缩重编码或删除原始证据。

原始证据与预览图、转码文件、截图、OCR 结果、整理后的副本必须分开保存，并明确标记文件类型及来源。

采集时记录原始文件名、文件大小、文件格式、采集时间、来源、采集方式及可获取的原始元数据。

对无法直接获取原始载体或原始数据的情况，必须如实记录限制、获取方式和原因，不得将副本冒充原件。

对需要系统权限、无法访问或采集失败的数据，必须明确提示，不得伪造采集成功记录。

2. 完整性校验与防篡改

采集完成后立即计算原始文件的 SHA-256 哈希值，并将哈希值与采集记录关联保存。

每次导出前重新计算哈希值，与首次计算结果比较；不一致时必须提示证据内容可能发生变化，并记录校验结果。

记录采集、查看、复制、导出、校验等关键操作的时间、操作类型、关联证据 ID 和执行结果。

操作日志采用追加式记录，不允许普通业务操作修改或删除历史记录；同时说明本地管理员、Root 权限或设备被控制时仍可能存在篡改风险。

不得将哈希校验通过表述为证据内容真实、来源真实或依法必然被采信。

3. 证据来源与真实性审查辅助信息

记录证据来源、生成方式、采集主体、采集时间、设备及系统环境、采集过程、存储位置和文件完整性校验结果。

时间信息必须注明来源，例如设备系统时间、用户填写时间或外部可信时间戳；不得把设备时间直接宣称为可信时间。

用户手动填写、补充或修改的说明必须单独记录，保留修改前后的内容及修改时间，不得与原始采集数据混为一体。

无法核实的信息必须标记为“未验证”或“未知”，不得自动补全、推断或生成虚假的来源、时间、身份及采集记录。

4. 电子签名与身份认证

不得把普通图片签名、手写签名截图、输入姓名或本地生成的签名图标宣称为符合《中华人民共和国电子签名法》要求的可靠电子签名。

如实现电子签名功能，必须明确签名主体身份核验方式、签名数据与文件的绑定关系、签名验证机制及密钥保护方式。

未实现法定条件验证的功能，只能标记为“本地签署记录”或“签名信息”，不得宣称具备可靠电子签名的法律效力。

5. 导出与证据交付

导出时必须保留原始证据文件，并同时生成证据清单及采集记录。

清单至少包含证据 ID、文件名、来源、采集时间、文件大小、SHA-256、采集方式、校验结果及异常说明。

对经过裁剪、转码、标注、OCR 或其他处理的文件，必须标记为处理副本，并保留与原始证据的关联关系及处理记录。

导出包必须包含必要的校验工具或明确的独立校验方法，确保接收方能够重新计算哈希并核对文件完整性。

对缺失文件、校验失败、采集异常或来源不明的证据，必须在清单中明确标记，不得静默忽略。

6. 法律效力表述限制

应用名称、界面、导出报告及用户提示中，不得使用“保证法律效力”“法院必然采信”“绝对真实”“不可伪造”等无法保证的表述。

可以表述为“证据完整性校验”“原始文件保全”“取证过程记录”“电子数据真实性审查辅助材料”等。

必须明确：工具能够辅助保全数据、记录取证过程和校验文件完整性，但不能单独保证证据的真实性、合法性、关联性或最终证明力。

区块链存证、哈希校验和本地日志只能作为相应技术事实的证明材料，不能直接证明上链前的数据真实，也不能替代法院依法进行的证据审查。

取证流程必须避免非法获取他人数据、绕过访问控制、侵犯隐私或超越用户合法权限。

7. 验收要求

为原始文件保护、哈希校验、操作日志、异常记录、导出清单及签名状态分别编写测试。

测试覆盖文件被修改、文件丢失、采集失败、系统时间异常、重复导出、处理副本与原件关联、日志异常等场景。

对未实现的功能、受 Android 权限限制的能力和无法验证的法律条件，必须明确标注，不得通过模拟数据或虚假成功状态通过验收。
## 产品定位

- 名称：TraceKeep（证迹）；Android 原生应用；个人使用；不强制注册；默认本地保存原始媒体；可选联网增强证据保全。
- 首版功能：录音、摄像头录像、系统授权录屏、GPS 轨迹、操作日志、SHA-256、哈希链、密钥签名、可信时间证明/第三方存证适配、证据包导出、独立验证工具、PDF 报告。
- 产品不以“生成一份看起来正式的 PDF”为完成标准，而以原始文件可保全、形成过程可说明、异常可披露、导出可复核、第三方凭证可独立验证为核心。

# 1. 最高优先级：法律与第三方服务可行性评估

## 目标

- 先确定需要提高哪一类证据能力，再选择服务；禁止先选某个“存证平台”后反向声称其一定有法律效力。
- 在正式开发前，完成法律场景清单、威胁模型、第三方服务尽调和费用估算。个人免费使用意味着应用自身免费，不代表第三方可信时间戳、电子认证、公证或存证服务一定免费。

## 必须调研并形成比较表

- 可信时间戳服务：服务主体、时间戳签发机制、签名验证方式、证书链、长期验证材料、API/SDK、价格、个人使用条款、数据上传范围、服务可用性及退出方案。
- 电子认证/数字签名服务：认证主体与资质、身份核验方式、密钥控制方式、签名对象、证书有效期与吊销检查、签名验证工具、费用及个人用户可用性。
- 第三方电子数据存证或区块链存证服务：运营主体、服务规则、原始数据还是哈希上链、提交回执、时间来源、证据导出、技术核验、争议处理、数据留存和删除规则、价格及隐私影响。
- 公证或其他线下保全流程：适用场景、预约/办理要求、需要提交的材料、是否支持电子数据保全、成本及时间。不得假定某服务可对任意手机录制过程提供公证。
- 必须明确：平台是否仅保存哈希、是否实际接收原始媒体、是否能够证明提交前数据的形成过程、是否支持独立验证、服务中断或企业停业后如何验证。

## 验收标准

- 输出 docs/LEGAL_AND_SERVICE_ASSESSMENT.md，列明官方法律来源、待律师确认的问题、候选服务及其官方条款/价格来源、数据流向、成本和风险。
- 至少比较 3 种方案：纯本地完整性保护、可信时间戳/第三方存证增强、必要时结合公证/律师指导的流程。
- 没有核实服务主体、条款、接口和价格之前，不得硬编码供应商、虚构接口或声称已经接入。
- 如果不存在完全免费且符合要求的第三方服务，清楚区分免费基础能力与可选付费增强能力，不得把付费服务设为应用运行前提。

# 3. 录音、摄像头录像与录屏

## 录音

- 用户明确发起录制；展示清晰状态；按 Android 版本正确使用麦克风权限、前台服务和通知；锁屏/切换应用后的持续行为必须真实设备验证。
- 记录开始、暂停、恢复、结束、权限撤销、设备中断、存储不足及封装失败。异常或未完成文件不得标记为完整封存。
- 记录真实编码、采样率、声道、文件大小和时长；不得将有损编码结果称为未经处理的原始采集数据。

## 摄像头录像

- 支持用户主动开始、停止及设备支持时的前后摄像头切换；记录真实分辨率、帧率、编码、音轨和异常状态。
- 媒体封装完成后再计算最终哈希。预览、缩略图、转码件与原始媒体分开保存，不能覆盖原始文件。
- 尊重相机/麦克风权限及其他应用安全限制；不得隐蔽录制或规避系统提示。

## 屏幕录制

- 使用 MediaProjection 的系统授权流程；遵守各 Android 版本对授权令牌、前台服务及停止回调的要求；每次会话按系统要求重新授权。
- 分别处理麦克风与内部音频，明确记录设备不支持、用户拒绝、系统停止及受保护内容不可录制等情况。
- 不能声称所有机型都能在锁屏后继续录屏或录制内部音频。

## 验收标准

- 真实设备测试正常录制、锁屏、切换应用、用户停止、权限撤销、系统中断、磁盘不足、文件封装失败。
- 每种录制方式分别记录设备型号、Android 版本、测试步骤、实际结果和未验证项；模拟器结果不能代替真实设备测试。

# 4. GPS、设备时间与事件日志

## 定位

- 支持录制前明确启用/关闭位置记录；按合理间隔记录坐标、定位时间、接收时间、精度及可获取的来源信息。
- 优先使用合法、必要的定位权限；不要无条件请求后台定位权限。若需要后台定位，先证明前台服务方案无法满足需求并解释原因。
- 定位缺失、权限撤销、定位关闭、无信号和精度不足都必须如实记录，不得补造坐标。

## 时间

- 分别记录设备墙上时钟、单调时钟、定位提供的时间、应用收到/写入时间，以及第三方时间戳的签发时间。
- 第三方时间戳应保存原始响应、签名、证书链/验证材料、请求摘要、服务商标识、算法和验证说明；按服务规范验证，不能只保存一个网页截图。
- 若系统时间跳变或墙上时钟与单调时钟的差值异常，记录可观察到的异常；不得声称能够发现所有时间修改。

## 操作日志

- 记录会话创建、实际开始/暂停/恢复/结束、权限事件、定位事件、异常中断、封存、哈希、签名、时间戳请求、导出和校验。
- 每个事件标注来源类型：用户操作、系统回调、应用观察或第三方响应。无法确认的事件不得写成确定事实。

## 验收标准

- 定位记录和日志均可导出并独立校验；时间字段含义有文档；缺失数据显式标记；模拟时间跳变测试不会悄悄改写历史记录。

# 5. 原始媒体保全、哈希链与数字签名

## 原始媒体与存储

- 优先使用应用私有存储保存原始文件；原始媒体、缓存、缩略图、报告和导出包分开。
- 使用唯一标识、临时文件、原子提交及封存状态；禁止覆盖式编辑；异常时保留可恢复信息并标记未完成。
- 记录源文件与导出副本的哈希；外部存储或文件选择器的信任边界要在报告中说明。

## SHA-256 与哈希链

- 对媒体封装完成后的实际文件字节流计算 SHA-256；大文件流式计算。校验状态区分通过、失败、缺失、未完成和无法读取。
- 事件使用明确版本化的规范化编码，定义字符编码、字段顺序、空值、数字表示、时区及哈希算法；每条事件包含序号和前一事件哈希。
- 对链头/最终清单进行签名。哈希链是防篡改检测机制，不是独立的可信时间证明；若攻击者能控制整个设备并重建全部数据，单靠本地链无法证明历史状态。

## 数字签名

- 私钥存放在 Android Keystore，绝不导出到证据包；导出公钥、算法、签名值、密钥标识及验证所需材料。
- 定义密钥丢失、密钥轮换、设备迁移和证书撤销的处理规则；不得换新密钥后假装是旧密钥。
- 如果采用第三方电子认证服务，需先核实服务主体、认证方式、证书验证及适用范围。应用自生成的本地密钥签名不能自动证明签名者真实身份。

## 验收标准

- 修改媒体一个字节、修改清单、删除中间事件、重排事件、修改签名、删除公钥等破坏性测试均得到准确的分项结果。
- 校验失败不覆盖、不自动修复原始材料；保留异常信息供用户导出。

# 6. 证据包、报告与独立验证

## 证据包

- 推荐包含 manifest.json、report.pdf、media/、location/、logs/、signatures/、timestamps/、receipts/、verification/ 和 README.txt。
- 清单包含应用版本、格式版本、会话 ID、录制类型、设备记录时间、文件大小/格式/哈希、位置数据、事件日志、哈希链、签名、第三方时间凭证、异常和缺失数据。
- 导出后重新读取目标文件并重新计算哈希；不覆盖同名文件；不导出私钥；失败时不得显示成功。

## PDF 报告

- 报告应列明原始媒体、哈希值、验证结果、时间来源、位置精度、异常中断、缺失区间、第三方凭证及验证结果。
- 明确区分：设备记录时间、第三方时间证明时间、文件哈希一致、数字签名有效、第三方平台回执，以及尚未证实的事实。
- 不得使用“司法鉴定报告”“法院认证”“百分之百有效”等误导性措辞。

## 独立验证工具

- 实现可离线运行的独立验证程序，不依赖手机数据库、原始私钥或网络。第三方时间戳的在线状态检查可作为附加检查，但必须单独标注。
- 验证文件清单、媒体哈希、位置与日志哈希、哈希链、数字签名、第三方时间戳/存证回执、路径安全、未引用文件及报告关键字段一致性。
- 输出 PASS、FAIL、WARN、SKIPPED，逐项解释原因；不得将“签名有效”误说成“身份已获外部认证”，也不得将“上链后未变”误说成“上链前内容真实”。

## 验收标准

- 导出包可复制到另一台电脑，在不安装原 App、不访问其数据库的条件下完成独立验证；对任一材料修改都能指出对应失败项。
- 第三方凭证能够使用服务商提供的官方方式验证，并保存必要的验证材料。

# 7. 第三方存证集成与成本控制

## 接口设计

- 定义 TimestampProvider、EvidencePreservationProvider、SignatureProvider 等接口，供应商实现与业务层解耦。
- 每次外部提交前显示：提交内容是完整媒体还是哈希/清单、上传数据范围、服务商、预计费用、隐私影响及失败处理；用户明确确认后才提交。
- 优先考虑仅提交文件哈希/清单以减少隐私暴露，但必须明确这只能证明服务商收到特定摘要，不能独立证明摘要对应的现场事实真实。
- 保存请求摘要、服务响应、服务商标识、请求/响应时间、凭证原文、签名和验证材料；网络失败时保留本地证据并标注未存证，不得伪造成功回执。

## 供应商选择

- 不得根据营销文案直接认定某平台“有完整法律效力”。以官方合同、技术规范、资质信息、验证方式、收费条款、隐私条款和争议处理规则进行评估。
- 首版可支持一个经过核实的服务商适配器，但同时保留本地方案和供应商替换能力。
- 如果没有合适的免费服务，允许用户不启用第三方服务；在 UI 和报告中准确显示该次记录没有第三方时间戳/存证。

# 8. 隐私、合法性与安全

## 隐私与合法录制

- 默认本地保存；联网只用于用户明确选择的可信时间戳、存证或验证服务。没有用户确认不得上传媒体、GPS、日志或设备标识。
- 不得实现隐蔽录制、自动偷录、规避 Android 授权、绕过受保护窗口或窃取其他应用数据。
- 对涉及他人声音、影像、个人信息、私人空间或敏感场景的录制，提供简明的合法性提示。应用无法替代用户判断录制行为是否合法。
- 提供数据删除确认、导出提醒及隐私说明。普通删除不应宣称为物理介质不可恢复擦除。

## 安全测试

- 检查权限最小化、网络请求白名单、日志脱敏、私钥保护、导出包路径穿越、恶意文件、数据库与文件不一致、依赖漏洞和许可证。
- 第三方 SDK 默认不允许读取媒体库或位置；只有在服务确实需要且用户明确同意时才传输必要数据。
- 建立依赖升级、证书失效、服务商停止运营和长期验证的处理说明。

# 12. 项目最终验收红线

## 以下任一项未满足，不得宣称“具备完整法律效力”或“已完成取证系统”

- 原始媒体不能被稳定保存，或异常中断后无法区分完整与不完整。
- 哈希、哈希链、签名或第三方凭证的验证结果存在假阳性。
- 报告隐瞒录制中断、定位缺失、时间异常或校验失败。
- 第三方服务的主体、条款、费用、验证方式尚未核实，却声称已实现可信存证。
- 把本地设备时间称为可信时间戳。
- 把哈希一致、数字签名有效或区块链存证等同于内容本身真实。
- 独立验证必须依赖原 App 的数据库或服务器才能完成。
- 尚未进行的真机测试被写成已经通过。
- 隐私告知、数据上传范围、录制合法性风险和第三方服务条款未完成审查。

- 推荐表述：‘TraceKeep 用于帮助用户记录音视频、保存操作与定位信息、校验文件完整性，并在接入相应第三方服务时保存可验证的时间或存证凭证。证据的真实性、合法性、关联性及证明力仍由具体事实和有权机关依法审查。’
- 禁止表述：‘录制后百分之百有效’、‘法院必定认可’、‘绝对不可篡改’、‘自动取得司法效力’。
