# TraceKeep 威胁模型（THREAT_MODEL.md）

> 依据：`PROJECT_REQUIREMENTS.md` §8（隐私、合法性与安全）、§5（原始媒体保全）、§12（最终验收红线）；`OPEN_SOURCE_ASSESSMENT.md`（第三方工具不集成决策）。
> 本文件记录**已识别的威胁、缓解措施与残余风险**。缓解措施中标注的阶段号指 `TECHNICAL_PLAN.md` §8 的开发阶段；**未实现前不得在任何界面或报告中宣称该缓解已生效**。
> 本文档不是法律意见；不宣称任何缓解措施能够保证证据被法院采信。

## 1. 系统范围与资产

### 1.1 受保护资产（按敏感度排序）

| 资产 | 说明 | 敏感度 |
|---|---|---|
| A1 原始媒体文件 | 录音、录像、录屏原始文件（含他人声音、影像、私人空间） | 极高（隐私） |
| A2 位置数据 | GPS 轨迹、精度、定位时间 | 极高（隐私） |
| A3 事件日志 | 会话操作、权限事件、系统回调、异常记录 | 高（行为画像） |
| A4 完整性材料 | SHA-256、哈希链、清单 manifest | 高（证据可信基础） |
| A5 签名密钥 | Android Keystore 私钥（不可导出）；导出公钥/密钥标识 | 极高（冒充风险） |
| A6 第三方凭证 | 时间戳/存证回执、响应原文、验证材料 | 高 |
| A7 证据包 | 上述全部内容的导出聚合体 | 极高 |
| A8 应用数据库 | Room 中的会话/事件/文件元数据 | 高 |

### 1.2 信任边界

```
┌─ 信任域 1：应用进程与私有存储（受 Android 沙箱保护）
│    ├─ 私有存储原始媒体 / 数据库 / 日志
│    └─ Android Keystore（硬件级密钥保护，视设备能力）
├─ 信任边界 A：应用 ↔ 外部存储 / 文件选择器（用户选择目标目录时，权限与信任状态变化）
├─ 信任边界 B：应用 ↔ 网络（仅用户明确确认的时间戳/存证/验证服务；默认不联网）
├─ 信任边界 C：证据包 ↔ 接收方/法庭（离开设备后完全脱离本应用控制）
└─ 信任边界 D：应用 ↔ 设备其他软件（其他应用、恶意软件、被接管的系统）
```

- **边界 A**：导出到外部存储或经文件选择器分享后，文件可被第三方应用读取；报告的「信任边界」章节必须说明。
- **边界 B**：第三方服务仅接收哈希/清单或用户确认提交的内容；服务商自身的留存与删除规则属阶段 0 调研范围（未完成，见 §9）。
- **边界 C**：证据包的保管与流转（复制、移交、提交）发生在用户侧；本应用无法控制，报告只能说明「导出后哈希复核」结果。
- **边界 D**：设备被 Root、被恶意软件控制或系统时间被修改时，本应用的本地防护能力有上限；必须在文档与报告中如实披露（需求 §5 哈希链说明、§4 时间说明）。

### 1.3 明确的能力非声称（Non-Claims）

本应用**不声称**、文档与界面**禁止**暗示：

1. 具备物理取证/磁盘镜像/写阻断能力（无此功能，也不模仿其表述）；
2. 能够证明录制内容在形成之初就是真实的；
3. 能够发现所有时间修改；
4. 哈希一致 / 签名有效 / 上链成功 = 内容真实或法院必然采信；
5. 普通删除 = 物理介质不可恢复擦除；
6. 设备被完全控制时仍能保证本地数据未被篡改。

## 2. 威胁主体

| 主体 | 动机/能力 | 主要目标 |
|---|---|---|
| T1 机会型第三方（捡到/借用设备者） | 一般操作能力，无专业工具 | 读取 A1/A2/A7 隐私内容 |
| T2 证据对立方 | 有法律动机与一定技术能力 | 质疑 A4/A6 完整性；主张录制被剪辑/伪造 |
| T3 技术能力较强的攻击者 | Root/恶意软件/物理访问 | 篡改 A1/A4/A8 或伪造时间线 |
| T4 应用自身缺陷（非恶意） | 编码错误、异常处理不当 | 产生假阳性/假阴性的校验结果（最危险的系统性风险） |
| T5 用户误用 | 无恶意但操作不当 | 非法录制、误分享证据包、在不可信环境验证 |
| T6 第三方服务商 | 商业/合规风险 | 服务中断、变更条款、停业、数据留存超范围 |

## 3. 威胁分析（按任务指定六域 + 两个补充域）

### 3.1 证据包导出风险

| E-3 | 导出失败却显示成功 | 用户误以为已有完整证据包 | 失败不得显示成功；不覆盖同名文件；失败时保留原始材料（§6，阶段 9） | 无 |

| E-6 | 兼容格式导出（若实现 D-007）导致用户误信「被专业工具认可」 | 过度信赖；法律误判 | 实测前不宣称兼容；导出物 README 附效力免责声明与校验说明（D-002） | 用户自行过度解读——文档措辞需持续审查 |

| E-8 | 水印配置了但实际未绘制（如 GL 效果初始化失败被静默吞掉） | 用户误以为视频含水印——报告与事实不符（验收红线级别） | 停止后写入 `watermark_frames` 帧计数事件；`drawnFrames=0` 必须如实披露；引擎启动失败**不降级**为无水录制（如实失败）；渲染器单帧失败静默但计数不增长（D-020，阶段 3/4 已实现） | 真机 GL 兼容差异——真机矩阵测试把关 |

### 3.5 密钥丢失与密钥管理风险

| # | 威胁场景 | 影响 | 缓解（阶段） | 残余风险 |
|---|---|---|---|---|
| K-1 | 设备丢失/损坏/重置导致 Keystore 私钥永久丢失 | 已有包无法由原密钥新签；无法再对旧会话「补签」 | 公钥/密钥标识随包导出；**旧包验证不依赖私钥**（独立验证工具只用公钥材料）；明确禁止用新密钥冒充旧密钥重签（§5，阶段 7） | 私钥丢失不可恢复（设计使然）；历史签名仍可验证 |
| K-2 | 密钥轮换后新旧材料混淆 | 验证混乱 | 密钥标识区分；轮换规则文档化；历史包保留旧公钥（§5，阶段 7） | 无 |
| K-3 | 设备迁移时误导出私钥 | 密钥泄露 | 私钥**绝不导出**到证据包（架构强制，红线测试：导出包中扫描无私钥）（§5，阶段 7/9） | 无 |
| K-4 | 本地签名被误解为「身份已认证」 | 法律表述越界 | 文案：本地自签=「本地签署记录」，非可靠电子签名；非外部认证身份（§「电子签名与身份认证」，全程） | 无 |
| K-5 | Keystore 被入侵应用滥用（同设备） | 冒充签名 | Keystore 硬件保护（视设备）；签名仅覆盖本应用生成的内容结构 | Root/系统级恶意软件的滥用难以完全防御——如实披露 |
| K-6 | 证书吊销状态不可查（自签无 CA） | 验证语义不清 | 验证器输出「签名有效（本地密钥）」并明确不含吊销语义；不声称 PKI 身份（§6，阶段 10） | 无（表述准确即无越界） |

| S-7 | 收费产生未预期费用 | 费用争议 | 提交前显示预计费用；付费服务不设为应用运行前提；无免费方案时允许不启用（§1/§7） | 服务商定价变动——核实日期标注 |

### 3.7 补充域：设备接管与平台级威胁

## 5. 残余风险汇总（必须如实披露、不可被文案掩盖）

1. **完全控制场景**：设备被 Root/恶意软件控制时，本应用无法保证本地数据与哈希链未被整体重建；本地方案对此只能披露，第三方时间戳/存证可以提供部分时间锚定（阶段 8 起，且依赖服务核实）。
2. **时间发现上限**：无法发现所有系统时间修改；墙钟/单调钟同时被改时记录可能自洽。
3. **接收方验证依赖**：证据包离开设备后，完整性保证依赖接收方执行独立验证；不做验证则篡改不可感知。
4. **服务商外部风险**：第三方服务停业、条款变更、在线验证失效（待 L-1 调研核对退出方案）。
5. **本地密钥不可恢复**：设备丢失即私钥丢失；历史签名仍可验证但不可补签。
6. **用户合法性与流转责任**：录制合法性判断与证据包分享范围由用户负责，应用仅提供提示与最小化默认值。
