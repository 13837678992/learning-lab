## 2. 项目目标与法律边界（不变，重申）

- 名称：TraceKeep（证迹）；Android 原生应用；个人使用；不强制注册；默认本地保存原始媒体；可选联网增强证据保全。
- 工程目标：提高证据材料的**可解释性、完整性、可复核性和保存质量**，不以「生成一份看起来正式的 PDF」为完成标准，而以**原始文件可保全、形成过程可说明、异常可披露、导出可复核、第三方凭证可独立验证**为核心。
- 能力边界（写入代码与文案的硬约束）：
  - 哈希只用于比较字节是否一致；哈希链只能帮助发现特定日志变动；数字签名只验证特定密钥签署的内容；可信时间戳/存证只能支持「某数据在某时间点已存在/已提交」。
  - 任何单项技术都不能单独证明现场事实真实、录制过程完整或行为合法；**不得将技术能力直接等同于法院必然采信**。
- 禁止表述：「录制后百分之百有效」「法院必定认可」「绝对不可篡改」「自动取得司法效力」「司法鉴定报告」「法院认证」等（需求 §12；`DECISIONS.md` D-006）。

## 3. 第三方工具不集成决策（需求：记录决策、原因与许可证风险）

### 3.1 决策（`DECISIONS.md` D-001）

**AndroidQF、MVT、ALEAPP、DroidCustos 的代码与二进制不进入本项目 APK，不作为运行时依赖，不打包分发。**

### 3.2 原因

1. **形态不匹配**：四个项目均为「桌面电脑 + USB/ADB」工具，无法在 Android 手机上运行；对端上录制（录音/录像/录屏）、GPS 采样、本地封存没有任何可调用能力（评估报告 §1、§5）。
2. **许可证复杂度**：
   - MVT License 1.1（AndroidQF、MVT）含第 3.0 条「同意使用限制」，要求数据所有者明确、知情、无胁迫同意——作为分发物的一部分会给 App 的合法分发引入额外条件与解释成本；MVT 官方自认该许可证不符合 OSI 开源定义与 FSF 自由软件定义。
   - DroidCustos 为 GPL-3.0-or-later，代码级复用触发传染义务（衍生作品须整体 GPL 化）。
3. **需求约束**：需求文档 §2 要求「无广告、分析或默认上传 SDK」；第三方组件与其精神相悖，且增加攻击面与隐私审计负担。
4. **无必要**：核心取证链路（录制 → 哈希 → 链 → 签名 → 封存 → 导出 → 验证）没有任何环节需要这四个项目。

### 3.3 许可证风险摘要（完整版见评估报告 §4）

| 项目 | 许可证 | 若复制代码 | 若捆绑二进制 | 独立进程/文档推荐 |
|---|---|---|---|---|
| AndroidQF（主体） | MVT License 1.1 | 须以同许可证开放源码 + 同意限制约束 | 须满足第 3.2 条（源码获取途径）+ 同意限制 | 不受传染 |
| AndroidQF（`android-collector` 子件） | MIT | 保留声明即可 | 保留声明即可 | 不受传染 |
| MVT | MVT License 1.1 | 同 AndroidQF | 同 AndroidQF | 不受传染 |
| ALEAPP | MIT | 保留声明即可 | 保留声明即可 | 不受传染 |
| DroidCustos | GPL-3.0-or-later | **传染：整体须 GPL 化并提供源码** | 触发 GPL 分发义务 | 不受传染 |

**本项目采取的最低风险路径**：一律不复制、不捆绑；仅在文档中作为「用户可自行安装的桌面工具」提及，并如实转述其许可证约束（尤其 MVT License 1.1 的同意条件）。借鉴设计思想（目录四分离、保管链字段、状态模型等）以自有代码干净重写，不构成代码复制。

### 3.4 允许的边界交互（不构成集成）

- **文档推荐**：在用户手册层面说明部分开源桌面工具可用于对导出物做**附加**复核（自愿安装、自担责任、与法律效力无关联）。
- **可选兼容格式**（默认列入观察项，待用户确认后才实现，见 `DECISIONS.md` D-007）：
  - 仅将 AndroidQF 的**公开归档结构**（ZIP + `acquisition.json` 风格元数据 + `hashes.csv` 风格哈希清单）作为可选导出变体的格式参考；只对齐文件结构，不复制代码。
  - **硬约束**：在完成实际桌面消费实测并通过验收前，任何界面、文档、报告**不得宣称**「兼容 MVT/ALEAPP/AndroidQF」或「已被某工具支持」；实测结果只允许表述为「格式可被某版本工具读取」，不得引申为任何效力。
  - 已核实事实（评估报告 §3.3/§3.4）：MVT 与 DroidCustos 均**不校验** `hashes.csv`；androidqf 无归档验证子命令。跨工具流转完整性责任在使用方。因此兼容导出**必须**配套 TraceKeep 自带校验说明/工具，且兼容导出失败不得影响原始证据包生成（需求 §7 原则）。

## 4. 总体架构

### 4.1 分层与模块划分（对齐需求 §2 目录建议）

```
tracekeep-android/
├── app/                     # 应用入口、UI（Jetpack Compose）、导航、权限流程、前台服务编排
├── core/
│   ├── model/               # EvidenceSession/EvidenceFile/EvidenceEvent/EvidenceLocation/状态机（纯 Kotlin，可 JVM 单测）
│   ├── storage/             # 应用私有存储、临时文件、原子提交、封存、恢复
│   ├── integrity/           # 流式 SHA-256、版本化规范编码、哈希链、清单校验
│   ├── crypto/              # Android Keystore 签名、密钥标识/轮换/丢失处理、公钥导出
│   ├── location/            # GPS 采样、精度/时间字段、缺失显式标记
│   ├── timestamp/           # TimestampProvider 接口层（实现待阶段 0 调研完成，见 §7）
│   ├── provider/            # EvidencePreservationProvider / SignatureProvider 接口层（同上）
│   ├── export/              # 证据包打包、manifest.json、导出后哈希复核、（可选）兼容格式导出
│   └── verify/              # 独立离线验证核心（可被独立验证工具与 App 内校验共用，但不依赖 App 数据库）
├── feature/                 # 录音/录像/录屏/GPS/日志查看/会话管理/导出向导等界面模块
├── docs/                    # 本文档及其余工程文档
└── tests/                   # 跨模块测试资源、固定测试向量、破坏性测试夹具
```

**依赖方向**：`app → feature → core/*`；`core/model` 不依赖 Android 框架（可 JVM 测试）；`core/*` 之间只允许单向依赖（model ← storage ← integrity ← export/verify），禁止环。

### 4.2 关键设计原则

1. **离线主链路**：录制、保存、哈希、签名、封存、导出、验证不依赖网络；联网能力（时间戳/存证/身份认证）全部在 `core/timestamp`、`core/provider` 接口后面，网络失败不得影响本地证据保存与封存（需求 §2、§7）。
2. **四分离**（借鉴评估报告 §7 的设计思想，干净重写）：原始证据（只读、封存后不可变）｜工作副本（预览/缩略图/转码，可再生成）｜分析结果（每次写入新目录）｜导出包（独立生成，导出后重新读回校验）。**任何处理结果不得覆盖原始证据**（需求 §5、导出红线）。
3. **显式异常状态**：状态区分「通过/失败/缺失/未完成/无法读取」，模块/会话状态显式记录（参考 AndroidQF 的 completed/partial/failed 模型思想）；异常或未完成文件不得标记为完整封存；不得伪造采集成功记录（需求 §3、§5、§7）。
4. **信任边界写入报告**：应用私有存储、外部存储、文件选择器、桌面流转的信任边界在报告中说明（需求 §5）。
5. **时间多源分离**：设备墙上时钟、单调时钟、定位提供时间、应用收到/写入时间、第三方签发时间分别记录，来源逐一标注；不得把设备时间称为可信时间戳（需求 §4、§12）。
6. **验证器独立性**：独立验证工具可离线运行、不依赖手机数据库、不依赖原始私钥、不依赖网络（第三方状态检查为可选项并单独标注）（需求 §6）。
7. **无隐蔽录制**：不实现偷录、不绕过 Android 授权、不规避系统提示、不绕过受保护窗口（需求 §3、§8）。

### 4.3 数据流（端到端）

```
[用户明确发起]
  录音 / 摄像头录像 / MediaProjection 录屏 ──┐
  GPS 采样（用户可开关）──────────────────┼─→ 会话（EvidenceSession，状态机）
  操作日志（追加式，来源类型标注）──────────┘        │
                                                   ▼
                                 媒体封装完成（异常/未完成显式标记）
                                                   │
                                                   ▼
                        流式 SHA-256（实际字节流）→ 版本化规范编码事件 → 哈希链
                                                   │
                                                   ▼
                        对链头/最终清单做 Android Keystore 签名（私钥不出包）
                                                   │
                                                   ▼
                        [可选] 第三方时间戳/存证提交（前置：费用/上传范围提示 + 用户确认）
                                                   │
                                                   ▼
        证据包导出：manifest.json + report.pdf + media/ + location/ + logs/
                    + signatures/ + timestamps/ + receipts/ + verification/ + README.txt
                    （导出后重新读取目标文件、重算哈希；不覆盖同名文件；不导出私钥）
                                                   │
                                                   ▼
        独立离线验证工具（PASS/FAIL/WARN/SKIPPED，逐项解释；不依赖 App 数据库/私钥/网络）
```

## 5. 核心技术设计要点（对应需求 §3–§8）

### 5.1 录制（录音 / 摄像头录像 / 录屏）

- 录音：AudioRecord/MediaRecorder 按设备能力选择；前台服务 + 通知（按 Android 版本使用合规的 `foregroundServiceType`）；记录真实编码、采样率、声道、大小、时长；**有损编码结果不得称为未经处理的原始采集数据**。
- 摄像头录像：CameraX/Camera2 按设备能力选择；支持用户主动开始/停止与前后摄像头切换（设备支持时）；记录真实分辨率、帧率、编码、音轨；**媒体封装完成后再计算最终哈希**；预览/缩略图/转码件与原始媒体分开保存。
- 录屏：MediaProjection 官方授权流程；遵守各版本对授权令牌、前台服务、停止回调的要求；每次都需系统授权；麦克风与内部音频分开处理；明确记录「设备不支持 / 用户拒绝 / 系统停止 / 受保护内容不可录制」；**不声称所有机型锁屏后可继续录屏或录内部音频**。
- 统一异常记录：开始/暂停/恢复/结束/权限撤销/设备中断/存储不足/封装失败全部进入追加式日志。

### 5.2 存储与封存

- 应用私有存储放原始文件；唯一标识 + 临时文件 + 原子提交 + 封存状态；禁止覆盖式编辑；异常时保留可恢复信息并标记未完成（需求 §2 阶段 2 的状态机与恢复机制）。
- 恢复机制：进程被杀/断电后启动时区分「完整封存 / 未完成 / 损坏」三态，未完成文件可导出但**必须显式标注**。

### 5.3 SHA-256 与哈希链

- 大文件流式计算（分块，常量内存）；校验状态五分类（通过/失败/缺失/未完成/无法读取）。
- 事件编码**版本化**：显式定义字符编码（UTF-8）、字段顺序、空值表示、数字格式、时区（UTC + 原始偏移）、哈希算法（SHA-256）；每条事件含序号 + 前一事件哈希。
- 对链头/最终清单签名；文档明确：**哈希链是防篡改检测机制，不是可信时间证明**；设备被完全控制时本地链无法证明历史状态。

### 5.4 数字签名（Android Keystore）

- EC（P-256）或 RSA 按 API 级别选择；私钥永不导出到证据包；导出公钥、算法、签名值、密钥标识与验证材料。
- 处理规则必须定义：密钥丢失（旧包只能验旧签，不得重签冒充）、密钥轮换（新密钥新标识、历史包保留旧公钥）、设备迁移（公钥随包导出，私钥不迁移）、证书撤销检查（本地自签无外部认证，如实标注「本地签署记录」；未经核实不得称「可靠电子签名」——需求「电子签名与身份认证」节 + 电子签名法边界）。
- 应用自生成密钥签名**不能**自动证明签名者真实身份。

### 5.5 事件日志（追加式）

- 记录：会话创建、实际开始/暂停/恢复/结束、权限事件、定位事件、异常中断、封存、哈希、签名、时间戳请求、导出、校验。
- 每事件标注来源类型：用户操作 / 系统回调 / 应用观察 / 第三方响应；无法确认的事件不得写成确定事实。
- 追加式：普通业务操作不可修改/删除历史记录；同时如实说明「本地管理员、Root 权限或设备被控制时仍可能存在篡改风险」。
- 用户手动填写/修改的说明**单独记录**，保留修改前后内容与时间，不与原始采集数据混为一体。

### 5.6 证据包与 PDF 报告

- 包结构（需求 §6 推荐）：`manifest.json`、`report.pdf`、`media/`、`location/`、`logs/`、`signatures/`、`timestamps/`、`receipts/`、`verification/`、`README.txt`。
- 清单内容：应用版本、格式版本、会话 ID、录制类型、设备记录时间、文件大小/格式/哈希、位置数据、事件日志、哈希链、签名、第三方时间凭证、异常与缺失数据。
- 导出流程：导出后**重新读取目标文件重算哈希**比对；不覆盖同名文件；不导出私钥；失败不得显示成功。
- PDF 报告：列明原始媒体、哈希、验证结果、时间来源、位置精度、异常中断、缺失区间、第三方凭证及验证结果；**明确区分**设备记录时间/第三方时间证明时间/哈希一致/签名有效/平台回执/尚未证实的事实；禁止误导措辞（见 §2）。
- 清单必须显式标记：缺失文件、校验失败、采集异常、来源不明——不得静默忽略。

### 5.7 独立验证工具

- 离线运行；不依赖手机数据库、原始私钥、网络；第三方时间戳在线状态检查为**附加项并单独标注**。
- 验证范围：文件清单、媒体哈希、位置与日志哈希、哈希链、数字签名、第三方时间戳/存证回执、路径安全（穿越/符号链接）、未引用文件、报告关键字段一致性。
- 输出 PASS / FAIL / WARN / SKIPPED 四级，逐项解释原因；表述纪律：「签名有效」≠「身份已获外部认证」；「上链后未变」≠「上链前内容真实」。

### 5.8 隐私与安全基线

- 默认本地保存；无用户确认不上传媒体、GPS、日志或设备标识；网络请求白名单；日志脱敏；导出包路径穿越防护；依赖漏洞与许可证审查。
- 对涉及他人声音、影像、个人信息的录制提供简明合法性提示；应用不替代用户判断录制合法性。
- 数据删除需确认；普通删除不宣称为物理不可恢复擦除。

### 5.9 第三方能力接口层（本期只做接口与「未启用」状态）

- `TimestampProvider`、`EvidencePreservationProvider`、`SignatureProvider` 接口定义；供应商实现与业务层解耦。
- 每次外部提交前显示：提交内容（完整媒体还是哈希/清单）、上传数据范围、服务商、预计费用、隐私影响、失败处理；**用户明确确认后才提交**；保存请求摘要、响应、凭证原文、签名、验证材料；网络失败保留本地证据并标注「未存证」，**不得伪造成功回执**。
- 在阶段 0 法律调研完成并经用户确认前：**不接入任何具体服务商、不硬编码 API、不在界面/报告中暗示已具备可信时间证明**；界面与报告如实显示「本次记录没有第三方时间戳/存证」。
- 优先设计「仅提交文件哈希/清单」的降隐私方案，同时明确其边界：只能证明服务商收到特定摘要，不能独立证明摘要对应的现场事实真实。
