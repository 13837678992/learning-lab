> 项目名称：fmac-front-main 企业级 qiankun 微前端脚手架
> 版本：v1.0
> 日期：2026-08-26
> 核心参考：docs/framework-migration-plan.md

# 1. 需求简述

## 1.1 项目背景

老系统采用 layout 基座 + 多个子应用的传统架构，所有应用部署在同一域名下。随着业务增长，暴露出子应用缺乏隔离（样式冲突、全局变量污染）、基座耦合严重、缺少企业级 Layout 能力（标签页、页面缓存）、构建部署不统一等问题。

## 1.2 项目目标

引入基于 qiankun 微前端的新框架基座（main-layout），替换老 layout 基座，实现：

1. 子应用之间完全隔离（样式隔离 + JS 沙箱）
2. 标准化的子应用接入规范（新增 3 文件 + 改造 2 文件）
3. 企业级 Layout 能力（标签页管理、页面缓存、持久化恢复）
4. 各子应用独立构建、独立部署
5. 渐进式接入，新老系统并行运行

## 1.3 项目范围

**包含：**
- main-layout 基座建设与能力完善（已完成）
- app-demo 子应用示例工程（已完成）
- 部署能力建设（Nginx 多域名/单域名方案，已完成）
- 7 个实际子应用适配接入（wms、frs、ocr、pic、platmng、fndrsch、workflow，待实施）
- SSO 登录对接（待实施）

**不包含：**
- 不采用 monorepo，不搬迁子应用代码
- 不重构子应用业务代码
- 不使用 Vue3 / Webpack5 / TypeScript

## 1.4 读者对象

技术负责人、开发人员、测试人员、项目经理。

# 2. 架构设计

## 2.1 改造前后架构对比

**改造前：** 老 layout 基座统一管理所有子应用，无隔离，统一部署。

**改造后：** main-layout 新基座通过 qiankun 加载各子应用，子应用独立部署，Nginx 统一路由分发。

```
浏览器 → Nginx → main-layout (:9000)
              → wms-server (:9001)
              → frs-server (:9002)
              → 其他子应用服务器...
```

## 2.5 部署架构

支持两种 Nginx 部署方案：

**方案一：多域名**
各子应用使用独立域名（main.example.com、wms.example.com 等），适合子应用数量少、需要强隔离的场景。

**方案二：单域名**
所有应用共用域名，通过路径区分（/、/wms/、/frs/ 等），适合统一管理。

静态资源（js/css）Nginx 设置 30 天长缓存（immutable）。

# 3. 关键点设计

## 3.1 子应用动态注册

基座从后端菜单接口获取子应用列表，动态生成 qiankun 注册配置，无需硬编码：

```javascript
// micro/apps.js
export function getApps() {
  var menu = store.state.menu;
  return menu
    .filter(function(item) { return item.entry; })
    .map(function(item) {
      return {
        name: item.app_code,
        entry: item.entry,
        container: '#subapp-container',
        activeRule: item.route
      };
    });
}
```

菜单数据中每个子应用包含 `app_code`、`entry`（子应用入口 URL）、`route`（激活路由规则）。后端配置即注册，前端零改动。

## 3.2 主子应用通信机制

基于 qiankun `initGlobalState` 实现双向通信，子应用之间不直接通信，所有跨应用交互通过基座中转。

**基座 → 子应用：**

| 字段 | 说明 |
|------|------|
| user.token | 认证令牌 |
| user.userInfo | 用户信息 |
| menu | 菜单数据 |
| permission | 权限列表 |

**子应用 → 基座：**

| action | 说明 |
|--------|------|
| route | 请求路由跳转 |
| refresh | 请求刷新当前页面 |
| logout | 请求退出登录 |
| TAB_OPEN | 请求打开标签页 |
| TAB_CLOSE | 请求关闭标签页 |
| TAB_REFRESH | 请求刷新标签页 |

基座侧 `platform/bridge.js` 的 `initBridge` 方法监听全局状态变化并处理各事件。子应用侧 `context.js` 封装 `navigateTo`、`requestRefresh`、`requestLogout` 等统一接口。

## 3.3 标签页管理

### 数据结构

```javascript
{
  id: '/home',              // 唯一标识（path + 排序后 query）
  title: '首页',            // 标签标题（来自 route.meta.title）
  path: '/home',            // 路由路径
  fullPath: '/home',        // 完整路径（含 query）
  name: 'Home',             // 组件名（用于 keep-alive）
  params: {},               // 路由参数
  query: {},                // 查询参数
  closable: false,          // 是否可关闭（首页不可关闭）
  keepAlive: true,          // 是否缓存
  isSubApp: false           // 是否子应用（子应用不参与 keep-alive）
}
```

### 核心机制

1. **自动创建**：路由 afterEach 守卫 dispatch addTab
2. **页面缓存**：Layout.vue 中 `<keep-alive :include="cachedViews">`，子应用路由时 `v-if="!isSubAppRoute"` 不渲染 keep-alive
3. **页面刷新**：REMOVE_CACHED_VIEW → viewKey++ → ADD_CACHED_VIEW
4. **持久化**：visitedViews 序列化存入 localStorage（key: fmac_tabs），afterEach 自动保存
5. **恢复**：应用启动时 restoreTabs（token 存在时）
6. **拖拽排序**：HTML5 Drag and Drop API，排序后持久化
7. **双击关闭**：仅 closable 标签生效

### 子应用容器

subapp-container 放置在 Layout.vue 级别（非 Home.vue 内部），使用 v-show 与 router-view 互斥：
- 主应用路由：显示 keep-alive + router-view，隐藏 subapp-container
- 子应用路由：隐藏 router-view，显示 subapp-container

## 3.4 Deep-link 恢复

```
未登录访问 /finance/detail?id=100
  → beforeEach 保存 redirect 到 localStorage（fmac_redirect）
  → 跳转 /login?redirect=/finance/detail?id=100
  → 登录成功
  → 读取 redirect（query 优先，其次 localStorage）
  → router.replace() 恢复原地址
  → afterEach 自动创建标签
```

双重保障：query.redirect（单次跳转）+ localStorage fmac_redirect（浏览器刷新场景）。

## 3.5 子应用适配标准

每个子应用统一适配流程（不动业务代码）：

| 步骤 | 内容 | 类型 | 改动量 |
|------|------|------|--------|
| 1 | 新增 `public-path.js` | 新增 | ~5 行 |
| 2 | 改造 `main.js` 导出 qiankun 生命周期 | 改造 | 入口文件 |
| 3 | 新增 `context.js` 通信模块 | 新增 | ~20 行 |
| 4 | 适配 `request.js` token + 401/418 | 改造 | 拦截器 |
| 5 | 路由 base 适配 | 改造 | router 配置 |
| 6 | Webpack dev-server 添加 CORS | 改造 | 1 行配置 |
| 7 | 后端菜单配置 entry + route | 配置 | 后端变更 |
| 8 | Nginx 配置路由 | 配置 | Nginx 变更 |

其中代码改动为"新增 3 文件 + 改造 2 文件"，配置步骤为 3 项。适配后子应用仍可在非 qiankun 环境下独立启动。

## 3.6 样式隔离

开启 qiankun `experimentalStyleIsolation`，自动为子应用样式添加作用域前缀。子应用 DOM 操作需限制在自身容器内。

# 4. 业务设计

本项目为框架迁移和工程改造项目，非传统业务系统。以下按核心业务流程描述。

## 4.1 登录流程

**当前实现（mock 登录）：**

```
用户输入账号密码 → POST /api/user/login
  → 后端返回 { token, username }
  → SET_TOKEN（localStorage fmac_token）
  → SET_USER_INFO
  → startSession()（启动 30 分钟超时检测）
  → syncUserState()（通过 bridge 同步到子应用）
  → 获取菜单 → 动态注册子应用 → 跳转首页
```

**目标实现（SSO 对接，待实施）：**

```
用户访问系统 → 无 token → 重定向到 SSO
  → SSO 登录 → 重定向回 main-layout?code=xxx
  → POST /api/auth/sso-login { code }
  → 后端验证 code → 返回 { token, userInfo }
  → 同上述流程
```

需改造文件：Login.vue（SSO 回调处理）、guards.js（SSO 重定向判断）、api/user.js（SSO token 交换）、auth.js（token 格式适配）。

## 4.2 菜单加载与子应用注册流程

```
登录成功 → GET /api/menu
  → 后端返回菜单数组（含 app_code、app_name、entry、route、permission）
  → 渲染侧边栏（AppSidebar）
  → 过滤有 entry 的菜单项 → 生成 qiankun 子应用配置
  → qiankun start() 注册子应用
```

## 4.3 页面浏览流程

```
用户点击菜单 / 标签
  → router.push(path)
  → beforeEach：检查 token
  → 路由匹配
    → 主应用路由：keep-alive + router-view 渲染
    → 子应用路由：v-show 显示 subapp-container，qiankun 加载/激活子应用
  → afterEach：设置页面标题、addTab、persistTabs
```

## 4.4 退出流程

```
触发退出（用户主动 / Session 超时 / 401/418 异常）
  → utils/logout.js 统一协调
  → 清除 token（localStorage）
  → bridge.notifyLogout()（通知所有子应用清除状态）
  → 清除标签持久化数据
  → 跳转登录页
```

## 4.5 子应用加载与卸载流程

```
路由匹配子应用 activeRule
  → qiankun 加载子应用 entry（HTML + JS + CSS）
  → 调用 bootstrap()
  → 调用 mount(props)
    → props 包含 onGlobalStateChange、setGlobalState、container
    → 子应用 setActions() 存储通信能力
    → 子应用 new Vue() 渲染到 container 内 #app

路由离开子应用
  → qiankun 调用 unmount()
    → 子应用 instance.$destroy()
    → 清除 DOM
    → instance = null
```

# 5. 接口设计

## 5.1 接口概览

本项目涉及的接口分为主应用接口和子应用接口。所有接口使用统一响应格式。

**统一响应格式：**

```json
{
  "code": 200,
  "data": {},
  "message": "success"
}
```

**认证方式：** Authorization header 传递 Bearer token。

**错误码：**

| 状态码 | 说明 |
|--------|------|
| 200 | 成功 |
| 400 | 参数错误 |
| 401 | 未授权（token 缺失或过期） |
| 418 | 账号异常（强制退出） |
| 500 | 服务异常 |

## 5.2 主应用接口

### POST /api/user/login

登录接口（当前为 mock，待对接 SSO）。

**请求：**
```json
{
  "username": "admin",
  "password": "123456"
}
```

**响应：**
```json
{
  "code": 200,
  "data": {
    "token": "mock-token-xxx",
    "username": "admin"
  },
  "message": "success"
}
```

### GET /api/user/info

获取用户信息。需 Authorization header。

**响应：**
```json
{
  "code": 200,
  "data": {
    "username": "admin",
    "role": "管理员",
    "avatar": ""
  },
  "message": "success"
}
```

### GET /api/menu

获取菜单数据（含子应用注册信息）。需 Authorization header。

**响应：**
```json
{
  "code": 200,
  "data": [
    {
      "app_code": "home",
      "app_name": "首页",
      "entry": "",
      "route": "/home",
      "permission": ["view"]
    },
    {
      "app_code": "wms",
      "app_name": "仓储管理",
      "entry": "//wms-server:9001",
      "route": "/wms",
      "permission": ["view"]
    }
  ],
  "message": "success"
}
```

菜单项字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| app_code | string | 应用唯一标识 |
| app_name | string | 应用显示名称 |
| entry | string | 子应用入口 URL（空字符串表示主应用页面） |
| route | string | 激活路由规则 |
| permission | array | 权限列表 |

## 5.3 子应用接口

### GET /api/demo/data

获取示例数据（app-demo 子应用）。需 Authorization header。

**响应：**
```json
{
  "code": 200,
  "data": {
    "items": [
      { "id": 1, "name": "数据项 1", "status": "active" }
    ]
  },
  "message": "success"
}
```

## 5.4 主子应用通信接口（非 HTTP）

通过 qiankun globalState 实现，详见第 3.2 节通信协议。

# 8. 非功能设计

## 8.1 性能

### 构建性能

- Webpack 4.47.0 构建，已验证零错误零警告
- style-loader@2.x + css-loader@5.x（兼容 Webpack4，3.x/6.x 不兼容）

### 页面加载性能

- 基座首次加载包含必要框架代码
- 子应用按需加载（路由匹配时才加载）
- Nginx 静态资源长缓存（js/css 30 天 immutable）

### 运行时性能

- qiankun JS 沙箱 + experimentalStyleIsolation，开销可控
- keep-alive 动态 include，仅缓存必要页面
- 标签页切换通过 router.push，无全量刷新

## 8.2 兼容性

### 浏览器兼容

基于 Vue 2.7 + Webpack 4 技术栈，默认支持现代浏览器（Chrome、Firefox、Edge、Safari 最新两个主要版本）。具体兼容范围待确认。

### 运行环境兼容

- Node.js 18（固定约束）
- Webpack 4（固定约束，禁止升级到 5）
- Vue 2.7.x（固定约束，禁止使用 Vue 3）
- 各子应用假设均为 Vue 2.x + Webpack（待确认实际技术栈）

### 新旧系统兼容

- 新老系统可并行运行，支持灰度切换
- 适配后子应用保留独立运行能力（非 qiankun 环境可独立启动）

## 8.3 用户界面

## 8.5 拓展性

### 新子应用接入

标准化流程，预计每个子应用 1-3 天工作量。后端菜单配置 entry + route 后，基座自动注册。

### 渐进式迁移

分三批接入子应用：

| 批次 | 应用 | 优先级 | 复杂度 |
|------|------|--------|--------|
| 第一批 | wms | P0 | 高（最复杂，优先验证） |

# 9. 程序设计

## 9.1 入口程序（main.js）

```
main.js 执行流程：
  1. 导入环境变量
  2. 创建 Vue 实例
  3. 恢复标签（restoreTabs，token 存在时）
  4. 初始化 qiankun 全局状态（initGlobalState）
  5. 初始化通信桥梁（initBridge）
  6. 启动 Session 超时检测（startSession）
  7. 获取菜单 → 动态注册子应用 → qiankun start()
```

## 9.2 路由守卫程序（guards.js）

```
beforeEach：
  1. 检查 token
     → 无 token：保存 redirect → 跳转 /login
     → 有 token 且访问 /login：跳转 /home
  2. 设置默认 meta（keepAlive、closable）

afterEach：
  1. 设置 document.title
  2. dispatch addTab（自动创建标签）
  3. dispatch persistTabs（持久化到 localStorage）
  4. 清除残留的 fmac_redirect
```

## 9.3 标签管理程序（store/tabs.js）

Vuex 模块，管理标签状态：

**State：**
- visitedViews：标签列表数组
- cachedViews：keep-alive 缓存组件名数组
- routerViewState：路由视图状态（用于刷新控制）

**Actions：**
- addTab：创建标签（去重）
- closeTab：关闭标签 + 自动跳转
- closeOtherTabs：关闭其他
- closeLeftTabs / closeRightTabs：关闭左侧/右侧
- closeAllTabs：关闭全部（保留固定标签）
- refreshTab：刷新页面（移除缓存 → viewKey++ → 恢复缓存）
- reorderTabs：拖拽重排
- persistTabs：持久化到 localStorage
- restoreTabs：从 localStorage 恢复

**Mutations：**
- ADD_VISITED_VIEW / REMOVE_VISITED_VIEW
- ADD_CACHED_VIEW / REMOVE_CACHED_VIEW
- REORDER_VISITED_VIEWS
- SET_ROUTER_VIEW_STATE

## 9.4 通信桥梁程序（platform/bridge.js）

```
initBridge(store, router)：
  监听 onGlobalStateChange
    → action === 'route'：router.push(path)
    → action === 'logout'：logout()
    → action === 'refresh'：dispatch refreshTab
    → action === 'TAB_OPEN'：dispatch addTab + router.push
    → action === 'TAB_CLOSE'：dispatch closeTab
    → action === 'TAB_REFRESH'：dispatch refreshTab

syncUserState(token, userInfo)：
  → setGlobalState({ user: { token, userInfo } })

syncMenuState(menu)：
  → setGlobalState({ menu: menu })

notifyLogout()：
  → setGlobalState({ action: 'logout' })
```

## 9.5 子应用生命周期程序

```
子应用 main.js：

bootstrap()：
  → 空操作（初始化资源由 qiankun 管理）

mount(props)：
  → setActions({ onGlobalStateChange, setGlobalState })
  → new Vue({ router, render: h => h(App) })
  → $mount(props.container.querySelector('#app'))
  → 暴露 window.microApp = { logout: requestLogout }

unmount()：
  → instance.$destroy()
  → 清除 DOM
  → instance = null
```

## 9.6 Session 超时检测程序（platform/session.js）

```
startSession()：
  → 监听 mousemove / keydown / click 事件
  → 每次事件更新 lastActiveTime

定时检测（每分钟）：
  → Date.now() - lastActiveTime > 30 * 60 * 1000
    → 是：执行退出流程
    → 否：继续检测

stopSession()：
  → 移除事件监听
  → 停止定时检测
```

## 9.7 Axios 请求程序（utils/request.js）

```
请求拦截器：
  → 从 localStorage 读取 fmac_token
  → 注入 Authorization: Bearer <token>

响应拦截器：
  → 2xx：返回 response.data
  → 401：清除 token → 跳转登录页
  → 418：清除 token → 强制退出
  → 其他错误：消息提示
```
