# Layout Tab 测试报告

## 一、Tab 打开测试

### 测试场景 1：主应用页面打开

操作步骤：
1. 登录后进入首页
2. 点击侧边栏菜单项

预期结果：
- 顶部标签栏自动生成对应标签
- 标签显示页面标题
- 当前标签高亮
- 路由地址同步

### 测试场景 2：子应用打开页面

操作步骤：
1. 子应用通过 bridge 发送 TAB_OPEN 事件
2. 携带 title、path、params 数据

预期结果：
- 主应用接收事件
- 自动创建对应标签
- 路由跳转到目标页面

验证方法：
```javascript
// 子应用发送
actions.setGlobalState({
  action: 'TAB_OPEN',
  title: '子应用页面',
  path: '/app-demo/page1',
  params: {}
});
```

## 四、页面恢复测试

### 测试场景 1：浏览器刷新恢复

操作步骤：
1. 打开多个标签页
2. 按 F5 刷新浏览器

预期结果：
- 标签列表完整恢复
- 当前活动标签恢复
- 路由地址保持一致
- 缓存页面重新加载（keep-alive 缓存丢失，符合预期）

技术实现：
- visitedViews 通过 localStorage 持久化
- 应用启动时自动恢复
- 路由 afterEach 持续同步

### 测试场景 2：登录恢复（深链接）

操作步骤：
1. 未登录状态直接访问 `/finance/detail?id=100`
2. 被重定向到登录页
3. 登录成功

预期结果：
- 登录后自动跳转到 `/finance/detail?id=100`
- 对应标签自动创建
- 参数完整保留

技术实现：
- beforeEach 守卫保存目标地址到 localStorage
- 登录成功后读取并跳转
- afterEach 自动创建标签

### 测试场景 3：刷新后登录恢复

操作步骤：
1. 打开 `/finance/list` 页面
2. 清除 token（模拟超时）
3. 刷新页面
4. 被重定向到登录页
5. 登录成功

预期结果：
- 之前的标签列表恢复
- 跳转到原始访问页面
