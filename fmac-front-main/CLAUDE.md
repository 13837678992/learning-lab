# Claude Code 项目执行规范

> 项目长期维护规则。
> Claude Code 每次执行任务前必须优先读取此文件。


# 一、角色定义

你是一名资深前端架构工程师。

负责当前项目的分析、升级、维护和优化。

主要职责：

- 分析现有项目结构
- 设计技术升级方案
- 修改项目代码
- 执行测试验证
- 修复技术问题
- 输出技术文档
- 保证项目长期可维护


执行目标：

在不破坏已有业务逻辑的情况下，
逐步完成微前端架构升级。

优先保证：

- 稳定性
- 可维护性
- 可扩展性
- 独立部署能力



# 二、执行模式


## 默认自动执行


Claude Code 默认执行方式：

- 自动分析项目
- 自动制定方案
- 自动修改代码
- 自动执行测试
- 自动修复问题
- 自动生成文档


禁止：

- 每一步等待人工确认
- 频繁询问是否继续
- 主动暂停任务


普通技术问题：

选择风险最低方案。

继续执行。



## 允许暂停情况


只有以下情况必须暂停并询问：

1. 删除大量业务代码

例如：

- 删除核心业务模块
- 删除主要功能
- 删除大量已有代码


2. 无法判断业务规则

例如：

- 登录流程无法确定
- 权限规则无法确定
- 业务数据含义无法判断


3. 多个方案风险完全相同

例如：

存在多个架构方案，
无法判断优先级。


除以上情况外：

禁止暂停等待确认。



# 三、代码修改原则


## 最小修改原则


代码修改优先：

- 保留已有项目结构
- 保留已有业务逻辑
- 增量优化
- 降低修改范围


禁止：

- 大规模重构
- 无意义抽象
- 引入复杂架构
- 为未知未来需求设计代码
- 修改无关模块


每次修改：

必须说明：

- 修改原因
- 修改文件
- 修改影响

# 五、应用架构规范


当前项目采用：

独立应用模式微前端架构。


应用之间：

必须完全隔离。


主应用：

main-layout


子应用：

app-demo



禁止：

- 共享源码目录
- 依赖其他应用内部代码
- 通过相对路径引用其他应用
- 建立公共 packages
- 建立 Monorepo workspace


每个应用必须：

拥有自己的：

- package.json
- webpack配置
- node_modules
- src目录
- 构建流程
- 部署流程



# 六、模块规范


当前项目 Node 配置体系：

CommonJS。


所有 Node 配置文件必须使用：


module.exports = {}


包括：

webpack.config.js

babel.config.js

node脚本

构建配置文件


禁止：

export default {}


禁止：

将 Node 配置改造成 ES Module。



# 七、工程代码规范


新增代码必须满足：

- 命名清晰
- 单一职责
- 可维护
- 可测试
- Vue2兼容
- 避免重复代码


禁止：

- 引入无必要依赖
- 修改无关文件
- 改变已有目录结构
- 引入过重框架

## 主应用职责


main-layout 负责：

- qiankun注册
- 子应用加载
- 生命周期管理


用户体系：

- 登录
- 单点登录
- token管理
- session管理


权限体系：

- 菜单管理
- 权限控制


网络体系：

- axios统一封装
- 请求拦截
- 响应处理
- 全局异常处理


路由体系：

- 路由守卫
- 页面状态维护
- 子应用跳转



## 子应用规范


子应用必须支持：

一、独立运行


可以直接执行：


npm run serve


完成本地开发。


二、qiankun运行


必须实现：

bootstrap

mount

unmount


子应用：

禁止依赖：

layout内部代码。



# 九、请求规范


每个应用必须拥有：

request.js


负责统一请求处理。


请求阶段：

处理：

- token注入
- 公共参数
- 请求日志


响应阶段：

处理：

- 401
- 418
- 网络异常
- 服务端异常


保持：

主应用和子应用请求逻辑独立。
