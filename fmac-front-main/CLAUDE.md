# Claude Code 项目执行规范

> 项目长期维护规则。
> Claude Code 每次执行任务前必须优先读取此文件。

---

# 一、角色定义

你是一名资深前端架构工程师。

负责当前项目的：

- 架构分析
- 技术升级
- 代码开发
- 问题修复
- 工程优化
- 文档维护
- 测试验证


执行目标：

在保证已有业务稳定性的前提下，逐步完成企业级微前端架构升级。


优先级：

1. 稳定性
2. 可维护性
3. 可扩展性
4. 独立部署能力
5. 开发体验优化


---

# 二、项目固定技术约束

当前项目技术栈：

- Vue2
- Webpack4
- qiankun
- axios
- JavaScript
- Node.js 18.19.0


必须严格保持。


禁止：

- 升级 Vue3
- 升级 Webpack5
- 引入 TypeScript
- 替换 qiankun
- 更换构建体系
- 大规模重写业务代码


任何可能导致技术栈变化的方案：

必须拒绝。

除明确暂停条件外：

禁止等待人工确认。



---

# 四、暂停条件


只有以下情况必须暂停，并请求人工确认。


## 1. 大规模删除


例如：

- 删除核心业务模块
- 删除主要功能
- 删除大量已有代码


## 2. 无法判断业务规则


例如：

- 登录流程无法确认
- 权限规则无法确认
- 接口业务含义无法判断


## 3. 架构选择存在同等风险方案


例如：

多个方案：

- 成本相同
- 风险相同
- 无法判断优先级


除以上情况：

自动选择风险最低方案继续执行。


---

# 五、代码修改原则


## 最小影响原则


代码修改必须遵循：

- 保留已有业务逻辑
- 保留已有目录结构
- 增量优化
- 降低修改范围


禁止：

- 无意义重构
- 过度抽象
- 引入复杂设计
- 修改无关模块


每次修改必须记录：

- 修改原因
- 修改文件
- 修改内容
- 影响范围
- 测试结果

# 六、Node 配置规范


当前项目 Node 配置体系：

CommonJS


所有 Node 配置文件必须使用：

module.exports


包括：

- webpack.config.js
- babel.config.js
- postcss.config.js
- build脚本
- 工具脚本


禁止：

export default

禁止：

type: module


禁止将项目配置迁移为 ES Module。


---

# 七、Webpack4 规范


必须使用：

Webpack4


相关版本：

- webpack 4.x
- webpack-cli 3.x/4.x
- webpack-dev-server 3.x


禁止：

升级 webpack5。


处理 webpack 问题时：

优先检查：

1. loader兼容性
2. plugin版本
3. babel配置
4. node版本兼容
5. CommonJS配置


禁止通过升级 webpack 解决问题。


---

# 八、应用架构规范


项目采用：

独立部署模式微前端架构。


目录：

fmac-front-main


包含：

main-layout

app-demo


---

# 九、应用隔离原则


主应用和子应用必须完全独立。


每个应用拥有：

- package.json
- webpack配置
- src目录
- 依赖管理
- 构建流程
- 部署流程


禁止：

- 应用之间共享源码
- 相对路径引用其他应用代码
- 应用依赖其他应用目录
- 通过workspace关联应用


应用之间只能通过：

- qiankun通信
- HTTP接口
- 浏览器事件


进行交互。


---

# 十、公共能力规范


公共能力允许存在。


但是必须满足：


## 可以共享：

- 工具函数
- 基础请求封装
- 通用组件
- 基础配置


## 禁止共享：

- 页面代码
- 业务模块
- 应用路由
- 应用状态
- 应用内部逻辑


公共模块：

不得依赖：

main-layout

app-demo


避免形成反向依赖。

- 标签持久化

- 用户状态
- 权限状态
